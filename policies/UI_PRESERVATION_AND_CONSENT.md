# UI Preservation and End-User Consent Policy

## Purpose

The agent's default responsibility is search visibility optimization, not redesign. Preserve the existing website's visual identity, UX and behavior.

## Protected by default

- CSS/SCSS, styling frameworks, design tokens and theme files.
- Colors, typography, font sizes, spacing, margins, padding, dimensions and breakpoints.
- Page layouts, grids, templates and component hierarchy.
- Header, footer, navigation, menus, buttons, forms and interactive components.
- Animations, transitions, hover states and responsive behavior.
- Existing visible text, copy, product descriptions, headings, labels and CTAs.
- Application logic, routes, APIs, authentication, payments and user journeys.

## Default permitted scope (subject to plan approval)

- Non-visible metadata such as title and meta description.
- Canonical and robots metadata.
- XML sitemap and robots configuration.
- Accurate JSON-LD structured data.
- Technical crawl/indexation fixes.
- Non-visual semantic improvements that preserve behavior and appearance.
- Image alt text only after classifying informative vs decorative images.

## Consent required

### Visible content
Obtain explicit approval for the exact proposed text and exact URL/section before changing:
- Headings and labels.
- Product/service descriptions.
- Body copy, FAQs, blog copy and landing-page copy.
- Visible CTA wording.
- Any new visible section or content block.

### UI/design
Obtain explicit approval for the exact visual change and affected components/pages before changing:
- Layout, styling, CSS, colors, typography, spacing, responsive design.
- Components, navigation, buttons, forms, visual hierarchy or animations.

### Production
Obtain separate approval for the exact tested release before production deployment.

## Enforcement

- "Make my website SEO-ready" is not consent to rewrite content or redesign UI.
- Plan approval is not blanket approval.
- Consent is scoped to a plan version, URL, file, content or component.
- If a change cannot be made without touching protected scope, stop and request consent.
- Report all pending opportunities rather than silently implementing them.
- Keep UI-related files protected in the change review process.
