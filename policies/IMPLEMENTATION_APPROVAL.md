# Implementation Approval Policy

A versioned plan must be presented before implementation.

Each plan item must include:
- Unique change ID
- Target URL and/or file
- Current state
- Proposed change
- Evidence and rationale
- Expected benefit (not a guarantee)
- Risk and effort
- Whether visible text changes
- Whether UI/design changes
- Validation method
- Approval status

Allowed statuses:
- Proposed
- Approved
- Rejected
- Changes requested
- Implemented
- Validated
- Deferred
- Failed
- Rolled back

Approval is explicit, versioned and scoped. A plan update that materially changes scope requires renewed approval. Visible content and UI changes require their own specific approval. Production deployment requires separate approval.
